# Рабочий процесс AIBox

Основной агент — координатор. Для задач разработки используй проектных субагентов: architect, estimator, coder-terra, coder-deepseek, tester и researcher. Не запускай агентов без необходимости для простого ответа. Передавай им конкретную задачу, ограничения, необходимые пути и результаты предыдущего этапа; у субагентов отдельный контекст.

Для разработки: при необходимости попроси researcher собрать данные и architect составить план; затем выбери кодера. Если пользователь явно назвал кодера или модель, используй его выбор без estimator. Иначе estimator оценивает ожидаемую полную стоимость написания задачи на DeepSeek Flash: строго больше $0.20 — coder-terra, не больше — coder-deepseek. Учитывай ожидаемые входные и выходные токены всех обращений кодера, цену и возможные повторы; не считай цену вызова оценщика частью этого порога. При неизвестной цене или существенной неопределённости честно сообщи об этом и консервативно выбери coder-terra. Качество и безопасность важнее экономии: если DeepSeek не подходит, выбери Terra и объясни почему. Оценка не является ограничением расходов API.

После изменений вызови tester, передав конкретный список файлов и проверок. При ошибке верни задачу кодеру и затем повторно вызови tester. Только после положительного заключения тестера для актуального состояния файлов поручай кодеру сделать коммит исключительно файлов задачи. При изменениях после проверки обязательно повторное тестирование. Не коммить существовавшие пользовательские изменения без явного разрешения; если невозможно безопасно отделить изменения, остановись и сообщи пользователю. Не делай push или развёртывание без отдельного разрешения. Не меняй колонку без согласия пользователя; не включай обновления её прошивки.

Запускай независимые исследования параллельно, когда это действительно полезно. Для долгих независимых задач используй фоновые вызовы и жди уведомлений; не опрашивай их постоянно. Не заставляй агентов дублировать чтение больших логов: для Go-тестов используй `python3 scripts/test-brief.py [аргументы go test]`, по умолчанию `./...`. Успех выводит только итог, ошибка — диагностические строки неуспешных пакетов и тестов с ограничением вывода. При недостаточной диагностике запускай точечный тест повторно. Никогда не скрывай ненулевой код или не объявляй неполную проверку успешной.

Контекст проекта: Go-прокси для Яндекс Станции; `internal/bridge` — протокол и диалоги, `internal/aibox` — настройки и команды, `internal/web` — панель, `internal/characters` — глобальные персонажи, `internal/llm`, `internal/providers`, `internal/search`, `internal/memory`, `internal/chats` — соответствующие подсистемы. Актуальное состояние проверяй через Git, README и код: эта краткая справка не заменяет их.
